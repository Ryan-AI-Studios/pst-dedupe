**Findings / blind spots:**

1. **The doubled ToPF is QC-invisible — the spec's causal story is unproven.** `folder_leaf_matches` accepts any output path that *ends with* the expected leaf (unique_pst_qc.rs:2378). Because the writer nests the entire source path (which already starts `Root/Top of Personal Folders/…`) under its own IPM root, the doubled segments sit strictly *ahead of* the expected leaf — pure prefix, fully absorbed by suffix matching. A corpus whose only anomaly were the double root would pass `folder_tree_matches`. So the INC0102784 hard_fail must come from one of the interactions the spec doesn't name: **(a)** a message-bearing output `Unique Mail` residual (residual-routed winners whose expected rows are skipped as empty keys — the residual allowance at :2463 only fires when the *expected* leaf is itself Unique Mail); **(b)** per-folder count distribution mismatch (e.g., the D-0070 prefix race splitting one logical leaf across slots in a way the exclusive-claim order turns into a mis-claim); **(c)** exclusive-claim starvation when expected keys share suffixes with different lengths ("inbox" vs "root/top of personal folders/inbox" — mixed path shapes across sources; longest-first claiming lets the longer key eat the shorter key's slots); **(d)** metadata-incomplete path (empty expected map + any mail folder ⇒ auto-fail, :2409-2428). **The fix locus differs per mode:** (a)→writer residual routing / scan locus capture; (b)→pre-seed sources (finding 3); (c)→QC matcher; (d)→metadata. Phase 0 must add an explicit "classify failure mode" gate, and it needs no operator re-run: the finding `detail` already dumps `out_folders`/`out_counts`/`expected` verbatim into `qc_findings.csv` (unique_pst_qc.rs:795-800). The spec's layout-vs-QC decision (§2.3 lock 2) is premature until that triage exists.
2. **Fix-the-layout has a provenance trap the spec doesn't scope: what exactly gets stripped.** Options are materially different: strip only leading exact sentinel segments (`Root`, `Top of Personal Folders`, case-folded) vs strip-the-first-source-segment-always. The latter eats meaningful source root names (e.g., a root named `Mailbox - Doe, John` is provenance — stripping it violates lock 1). Also decide the interaction with the multi-source prefix: for INC0102784 the `<mailbox>` segment appears to come from *inside* the source trees, so a file-stem prefix on top duplicates provenance rather than adding it. The tree contract (DoD-2) must name the sentinel list, the case-fold rule, and the prefix policy as one coherent rule, not three ad-hoc behaviors.
3. **D-0070-multi-source-stream-prefix is cheaply closable, not just "conflated".** The plan's risk table treats the prefix race as a thing to separate out; but the CLI knows the full source set before writing (it already iterates winner `source_path`s for `store_key_material`, unique_pst_cmd.rs:2064-2070) while `IncrementalFolderPlan` starts with empty `sources_seen` and only stabilizes prefixes once a second source *appears in stream order* (production.rs:2408-2416). Passing the known source list (e.g., via `WritePstOpts` pre-seed) makes prefixes stable from message 1 with ~zero risk. If Phase 0 triage lands on mode (b), this is the whole fix; even otherwise, do it here and close D-0070 properly rather than narrowing it again.
4. **Latent QC hard-fail: `is_system_folder_path` asymmetry on Deleted Items.** Output slots exclude any path ending `/deleted items` (unique_pst_qc.rs:2492) — Deleted Items is a real content folder and winners can include it (`FolderClass::DeletedItems` is only a scoring rank, keepset.rs:131/168) — while expected keys get no such filter (:765-772). Any export with mail in Deleted Items fails `folder_tree_structure` forever, count match or not. Symmetrically note the exact-match arms (`top of personal folders`, `ipm_subtree`, …) are dead code for output paths, which always start `root/…` under this digest. If 0095 touches the QC at all, fix the asymmetry or prove the corpus can't hit it; add a Deleted-Items fixture row either way.
5. **Residual `Unique Mail` folder is created even when empty in preserve mode** (production.rs:2376-2384) — the spec's own evidence lists it in the output. Counsel-visible noise in an otherwise preserved tree; suppress-when-empty (or keep-as-marker) belongs in the DoD-2 contract.
6. **Verification and ledger-entity gaps in plan/DoD-4.** The commands test only `unique_pst_qc_0080`; a layout fix lands in `production.rs` and must update writer tests that currently assert the exact shapes under change (writer_v1.rs:367-380 asserts `Root/Top of Personal Folders/Unique Mail`) — add `cargo test -p pst-writer`.
